# Context Intelligence v2 - Architecture

## Vue d'Ensemble

Le module Intelligence v2 est une refonte data-driven du système d'adaptation contextuelle automatique de Symbion.

### Objectifs

- **Data-driven** : Pas de mappings hardcodés (ex: "JetBrains → focus") dans le core
- **Expliquable** : Why-chain pour chaque prédiction
- **Humble** : Sait dire "Unknown / insufficient data"
- **Découplé** : Modules testables < 300 lignes chacun
- **Progressif** : Migration shadow mode sans casser l'existant

### Pipeline Cible

```
Signal → Features → Vector → Inference → Sessions → Decision
```

## A1. SignalBus + FeatureRegistry

### Concept

Tout signal entrant devient une Feature typée, versionnée, avec TTL et source.

### Structures

```rust
/// Signal brut (venant modules/agents/plugins)
pub struct SignalEvent {
    pub source: String,        // "agent.pc-bureau", "sensor.chambre"
    pub signal_type: String,   // "process.list", "env.temperature"
    pub value: SignalValue,    // Bool/Int/Float/String/List
    pub timestamp: DateTime<Utc>,
}

/// Feature typée avec TTL
pub struct FeatureSample {
    pub feature_id: String,    // "process.category.ide"
    pub value: FeatureValue,   // bool/f32/enum
    pub confidence: f32,       // 0.0-1.0
    pub source: String,        // "classifier.process"
    pub timestamp: DateTime<Utc>,
    pub ttl_seconds: u32,      // expiration
}

/// Registre en mémoire avec expiration
pub struct FeatureRegistry {
    features: HashMap<String, FeatureSample>,
    subscribers: Vec<Sender<FeatureUpdate>>,
}
```

### Features Initiales

| Feature ID | Source | Type | Dérivé de |
|------------|--------|------|-----------|
| `agent.online` | agent heartbeat | bool | présence MQTT |
| `agent.idle.seconds` | agent heartbeat | u64 | dernière activité |
| `agent.cpu.usage` | agent heartbeat | f32 | metrics.cpu |
| `process.category.ide` | classifier | bool | process list + rules |
| `process.category.media` | classifier | bool | process list + rules |
| `net.ssid` | agent heartbeat | string | network_ssid |
| `env.temperature` | sensor | f32 | temperature_c |
| `time.hour` | kernel | u8 | chrono |
| `time.is_weekend` | kernel | bool | chrono |

### Process Classifier (Externe)

Le core NE CONNAÎT PAS les noms d'applications. Un classifier externe:
- Reçoit `process.list` via MQTT
- Publie `process.category.ide = true` si JetBrains/VSCode détecté
- Règles configurables dans `config/process_categories.toml`

## A3. Inference (Case-Based + Weighted Voting)

### TrainingSample

```rust
pub struct TrainingSample {
    pub vector: ContextVector,
    pub chosen_mode: String,
    pub source: SampleSource,  // UserCorrection > MFA > Automation > Bootstrap
    pub timestamp: DateTime<Utc>,
    pub weight: f32,  // décroît avec le temps
}

pub enum SampleSource {
    UserCorrection,  // Poids 1.3x - explicit user intent
    MFA,             // Poids 1.0x - validated by user
    Automation,      // Poids 0.8x - inferred
    Bootstrap,       // Poids 0.5x - initial rules
}
```

### Algorithme

1. Calculer similarité (cosine) entre `vector_current` et k échantillons
2. Vote pondéré par : `similarité × récence × source_weight`
3. Output : `Prediction { mode, confidence, alternatives, why }`
4. Si `confidence < 0.25` → `mode = "unknown"`

### Storage

- Max 2000 samples en mémoire
- Compaction périodique (clustering léger)
- Export JSON pour debug: `GET /v1/intelligence/samples/export`

## A4. Session Manager

### Structure

```rust
pub struct ActiveSession {
    pub mode: String,
    pub started_at: DateTime<Utc>,
    pub last_confirmed_at: DateTime<Utc>,
    pub stability_score: f32,  // 0.0-1.0
    pub source: SessionSource, // Predicted / Manual / Override
}
```

### Hysteresis

| Paramètre | Valeur | Description |
|-----------|--------|-------------|
| `entry_threshold` | 0.60 | Seuil pour entrer dans un mode |
| `exit_threshold` | 0.40 | Seuil pour quitter (< entry) |
| `min_duration` | 5 min | Durée minimum avant switch |
| `cooldown_after_manual` | 30 min | Cooldown après changement manuel |

### Override Expiry

- Event `OverdriveExpired` → recalc session → propose transition
- Respecte les overrides manuels jusqu'à expiration

## A5. Integration Decision Engine

### Règles

- **Aucun changement** sans `DecisionEngine.decide(Action::ForceMode{...})`
- **Auto-apply** uniquement si:
  - `confidence >= auto_apply_threshold` (0.60)
  - Session stable (>= 5 min) OU pattern établi (>= 3 occ)
  - Guards OK (pas d'override actif, pas de changement manuel récent)
- **Sinon**: suggestion (notification) ou log silencieux selon anti-spam

### Feedback Loop

```rust
pub enum DecisionSignal {
    ApprovedAuto,  // +0.30 modifier
    ApprovedMFA,   // +0.15 modifier
    Denied,        // -0.30 modifier
    Expired,       // 0.0 (no learning)
    Blocked,       // -0.10 to -0.30 (category-dependent)
}
```

### Config Flag

```toml
[intelligence]
mode = "legacy"  # legacy | v2 | shadow
```

- `legacy` : Pipeline actuel (v1)
- `shadow` : v2 calcule mais n'applique pas (logs comparaison)
- `v2` : Nouveau pipeline, ancien devient fallback

## Risques et Mitigations

| Risque | Impact | Mitigation |
|--------|--------|------------|
| Régression accuracy | HIGH | Shadow mode 2 semaines avant switch |
| Cold start sans données | MEDIUM | Bootstrap scheduler + decay rapide |
| Performance (2000 samples) | LOW | Similarité pré-calculée, indexation |
| Breaking changes API | MEDIUM | Endpoints v2 séparés (`/prediction2`) |
| Classifier externe manque | LOW | Fallback sur features brutes |
